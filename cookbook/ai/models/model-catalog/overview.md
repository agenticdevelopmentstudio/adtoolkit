
The model catalog is the shared model table shipped as a bundled resource
(`model-catalog.json`): one model entry per canonical model id, independent
of which gateway serves it, plus a per-(template id, spelling) offering table
for the terms (context window, output limit, token prices) that genuinely
differ between gateways. It is a **logic** component — no visual surface —
used by every provider template to answer "what do we know about this model,
and what does this gateway charge for it." Resolving a model for a template
merges the shared model facts, the matching offering, and a template's
curated model detail into one resolved model for display. The catalog is
generated by build tooling from a public catalog and committed as a bundled
resource; the shared catalog instance loads it once, falling back to an
empty (never absent) catalog if the resource is missing or unreadable.
