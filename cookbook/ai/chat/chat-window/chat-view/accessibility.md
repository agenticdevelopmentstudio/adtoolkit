
- **Role/trait**: Not applicable — unlike a single-purpose control, the component sets no accessibility role on itself; it is a container whose children (the composer field, the send button, the transcript) carry the platform's own default roles.
- **Label requirements**: The prompt label, status label, composer field, and send button carry the accessibility identifiers `ai-chat.prompt`, `ai-chat.status`, `ai-chat.input`, and `ai-chat.send-button` respectively (see **accessibility-identifiers**), and the send button's icon carries the accessibility description `Send`. The composer field itself has no accessible-label assignment and no programmatic association with the prompt label; its only textual cues are an accessibility *identifier* (a UI-test hook, not a spoken label) and a placeholder string, which is not guaranteed to be treated as the field's accessible name by assistive technology.
- **Announce state changes**: The typing indicator's appearance/disappearance and a row's selection change are drawn visually (see States) but no assistive-technology announcement accompanies either in this source. Row selection has a real keyboard path (arrow keys, Return, letters — see **arrow-key-selection**): a screen-reader user moving the selection with the keyboard has no source-confirmed way to hear which row is now selected.
- **Minimum tap target**: Not applicable in the touch sense — this is a pointer-driven component; the 44×44pt minimum applies to touch targets, not to mouse-driven controls. The send button's own clickable area is whatever the platform derives from its 18pt icon content plus its default button metrics; no explicit minimum-size constraint is set on it in this source.
