
- **Empty message text**: An empty `message.text` produces zero glyphs; the measurement's line-fragment walk never executes, so `lineCount` is `0`. `isExpandable` is `false` for any `lineLimit` (0 is never greater than a limit), so the toggle stays hidden and the bubble collapses to whatever the timestamp (if any) and padding come to.
- **`lineLimit = 0`**: A limit of zero never lets the truncation walk advance from its starting offset, so the truncation step's own boundary guard then fails and produces no cut point. The net effect: `isExpandable` is `true` for any non-empty text (any positive `lineCount` exceeds `0`), so the toggle is shown, but the text is never actually cut down — the full message renders regardless of `isExpanded`. A caller passing `lineLimit = 0` gets a toggle that has nothing to expand (see Platform Notes for the exact internal guard).
- **Message text that is entirely whitespace/newlines and exceeds `lineLimit`**: The truncation step searches backward for the last non-whitespace character before appending the ellipsis; if the portion up to the cut point is all whitespace, that search finds nothing, and no truncation is applied. As in the `lineLimit = 0` case, `isExpandable` is still `true` and the toggle still shows, but the text is displayed in full, untruncated, with no ellipsis.
- **A single unbroken run of characters wider than the text width**: No paragraph style or line-break mode is set on the text; wrapping such a run falls to the platform's own default word-wrapping fallback, which force-breaks a word that cannot fit on a line of its own.
- **Degenerate `maxWidth`** (at or below twice the horizontal text padding, i.e. 24pt): the text width available for measurement becomes zero or negative. The component performs no minimum-width guard on this caller-provided value; behavior at that point is whatever the platform's own text-layout system does with a non-positive width, which this file does not define further (see Platform Notes).
- **Boundary values**: `lineLimit` of exactly the message's laid-out line count is the `truncation-suppressed-when-not-needed` boundary — see chat-bubble-024. `isExpanded` toggling with no palette yet applied is a no-op — see chat-bubble-035.
- **Concurrent access**: Not applicable. The component is a view; all of its mutable state (`isExpanded`, the last-applied theme palette, the layout constraints) is read and written only from the platform's main-thread event handling (see Platform Notes), which is correct for a view that is never touched off the main thread.
- **Error states**: Not applicable. The component has no dependency on a network, database, or file-system call; it renders only the `ChatMessage` and `SemanticPalette` values it is given.
- **Offline/disconnected state**: Not applicable, for the same reason — this view performs no networking of its own.
- **Message text mutated after construction**: The component holds the message as an immutable snapshot taken at construction. The message's text field is itself mutable elsewhere in the codebase (mutated in place while a streaming assistant reply grows), but this component never observes that later mutation; a caller must construct (or a host row must rebuild) a new instance of the component to show updated text.
