
- **Role**: Generic container; the component itself sets no custom accessibility role or element grouping.
- **Label**: The component sets no accessibility label on the bubble container. The message text reaches assistive technology through the underlying text element's own default accessibility exposure. The expand toggle is the only element the component labels explicitly: its accessibility label and description are both set to "Show the whole message" / "Show less" per **expand-toggle-icon-and-label**; it is also tagged with a test-identification marker, not for assistive-technology wording (see Platform Notes).
- **State announcement**: The toggle's label and icon swap when `isExpanded` changes, so assistive technology reads the new label the next time it visits the button, but the component posts no explicit accessibility notification to announce the change proactively. No other state in this component (role, work-output dimming, border) is announced beyond what the color/text change itself implies.
- **Minimum tap target**: The 44×44pt minimum is a touch-input guideline; this is a pointer-driven control on a platform whose own interface guidelines set no equivalent minimum. The expand toggle's actual click target is 22×22pt.
- **Color dependence**: In `.speaker` style, `.user` vs `.assistant` is distinguished only by the theme's bubble/text color roles — the component provides no non-color cue (icon, position, label) of its own. In `.terminal` style this is deliberate and total: both conversational roles resolve to the *same* fill, text, and border, because the row that hosts a terminal-style bubble already states who is speaking in a header line above it; color is not how that style tells user from assistant.
- **Keyboard path (traced through the host)**: The component itself has no keyboard path for `onSingleClick`/`onDoubleClick` — it handles only pointer clicks and does not participate in keyboard focus or key-event handling on its own. In this component's actual usage, though, the gap is filled one level up: its host supplies row-level keyboard handling that moves a row selection with the arrow keys, invokes the same action as a double-click open on Return, jumps to the source conversation on Shift-Return, and invokes the same open/jump/expand-toggle actions on a small set of bare-letter shortcuts. The hosting row view wires the bubble's single-click callback to row selection and its double-click callback to the same open action the Return key invokes. So a keyboard-only user reaches equivalent behavior through the transcript's row selection, not through this component in isolation (see Platform Notes for the exact hosting types).
