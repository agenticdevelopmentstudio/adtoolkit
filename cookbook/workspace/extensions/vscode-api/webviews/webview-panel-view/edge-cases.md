
- **Null/empty input**: An empty `html` string is the initial value and loads as an empty extension page; an absent `state` is the ordinary "the page never called `setState`" case, and the injected bootstrap embeds it as `undefined` rather than `null` so an extension can tell a first run from a restore. Empty `viewType`/`title` strings are accepted verbatim — this component never validates them, since they are the extension's own declared values.
- **Boundary values**: An `externalOpenInterval` of `0` disables the external-open rate limit entirely, since elapsed time is never negative; the value is not clamped, because it exists only for tests to shorten and production code never assigns it. A second reveal request before any listener exists overwrites the first — only the most recent value replays (`reveal-deferred-request-overwritten`) — and a reveal retained this way survives disposal, since disposing the panel does not clear it; installing a listener afterward still replays it once even though the panel is already disposed (`installing-reveal-listener-replays-deferred-reveal`).
- **Concurrent access**: The whole component is confined to a single, serialized execution context (MUST, see `thread-confined-access`), which serializes every read and write of the page state, the disposed flag, the placement flags, and every callback. A message the page sends arrives through the message relay's own callback, which the relay re-enters onto the confined execution context explicitly rather than trusting that callback's own isolation, so a page message cannot race the confined context even if the webview were to deliver it from an unexpected queue.
- **Error states**: A posted-message value the webview cannot bridge (for example, a URL object) is dropped with a logged error and a `false` return, never a crash. A `setState` value that cannot be encoded as JSON (for example, a JavaScript `Date`) is dropped with a logged error, leaving the previously persisted state untouched and firing no restoration callback — a message is lost, not a state erased. A script message whose shape the relay does not recognize is dropped silently, treated as a hostile or malformed page rather than a bug to surface. Requesting a reveal, or relying on the deferred-removal path of disposing the panel, with no listener ever installed and none pending, does nothing — matching the upstream behavior for a panel whose presenting window is already gone. Disposing the panel a second time is a no-op, not an error.
- **Offline or disconnected state**: Not applicable to this component directly — it is not a network layer. Whatever the extension's rendered page does over the network happens entirely inside the page's own JavaScript, outside this component. The one network-adjacent behavior this component owns, opening an `http`/`https` link in the user's external browser, does not depend on this app's own connectivity.
