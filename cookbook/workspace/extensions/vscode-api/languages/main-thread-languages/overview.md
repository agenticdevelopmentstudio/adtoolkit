
This component is the `vscode.languages` namespace adaptor's shell and, so far, its only two members: `setLanguageConfiguration` and `getLanguages` (`vscode.d.ts` and `:14733`). `setLanguageConfiguration` validates its arguments, translates the JavaScript configuration object into a language configuration value through a family of value types that mirror `vscode.d.ts`'s `LanguageConfiguration` and its nested shapes (`CommentRule`, `IndentationRule`, `OnEnterRule`, `AutoClosingPair`, and the regex value every regex-bearing field decodes to), stores the result in an injected language configuration store keyed by an opaque handle, and hands back a `Disposable` that removes exactly that registration. `getLanguages` answers a resolved promise built from an injected language vocabulary's `languageIdentifiers`, read fresh on every call. Per this component's own documented contract ("Ruling 8"), this adaptor validates, translates, stores, and hands back — it applies nothing to any editor; nothing among the given sources reads a stored language configuration value back out today, which is why the language configuration store exists at all — so disposal has something real to undo — rather than because any consumer needs the stored value. The host language vocabulary (see Host Language Vocabulary; read for context, not part of this component) is the production language vocabulary: it composes the built-in language catalogue with the contribution point's contributed language identifiers. This component depends only on the language vocabulary's own contract, never on that composition directly, and a test hands it a double instead.
