
- **serialized-regexp-decode**: decoding a regex value MUST return a value carrying `pattern` set to the source's string-valued `source` property and `flags` set to its string-valued `flags` property, and MUST decode to nothing for `undefined`, `null`, or any value missing either property as a string.
- **serialized-regexp-verbatim-storage**: a regex value MUST store `pattern` and `flags` as the two plain strings read from the JavaScript `RegExp`, never as a pre-compiled regex-engine representation, so the exact `flags` string JavaScript supplied is preserved and can still be inspected later.
- **regexp-flag-mapping**: translating a regex value's `flags` to the platform regex engine's own option set MUST map an `i` flag to case-insensitive matching, an `m` flag to multiline anchor matching, and an `s` flag to dot-matches-newline matching, and MUST NOT set any option for a `g`, `y`, `u`, `d`, or `v` flag, none of which has an equivalent option.
- **line-comment-two-shapes**: decoding a line comment value MUST decode a JS string value to the string form, MUST decode an object carrying a string-valued `comment` property to the rule form with `noIndent` read from the object's `noIndent` property and defaulted to `false` when absent or not a boolean, and MUST decode to nothing for `undefined`, `null`, or any other shape.
- **comment-rule-requires-one-member**: decoding a comment rule value MUST decode to nothing when the source is not an object, and MUST also decode to nothing when both `lineComment` and `blockComment` fail to decode, even though each is independently optional in the external API's declared shape.
- **character-pair-shape**: decoding a character pair value MUST decode to nothing unless the source is a JS array whose index `0` and index `1` are both strings, read into `open` and `close` respectively.
- **character-pair-array-drops-invalid-elements**: decoding an array of character pair values MUST use the shared array-length helper to bound the walk and MUST drop any element that fails a character pair value's own decode rather than failing the whole array.
- **indentation-rule-requires-both-patterns**: decoding an indentation rule value MUST decode to nothing for the entire rule when either `decreaseIndentPattern` or `increaseIndentPattern` fails to decode as a regex value, and MUST independently decode `indentNextLinePattern` and `unIndentedLinePattern` as optional fields when the two required patterns are present.
- **indent-action-raw-values**: `IndentAction` MUST expose `none == 0`, `indent == 1`, `indentOutdent == 2`, and `outdent == 3`, matching `vscode.d.ts`'s declared numeric values exactly.
- **enter-action-requires-indent-action**: decoding an enter action value MUST decode to nothing for the entire action when `indentAction` is not a JS number whose exact integer value maps to a defined `IndentAction` case, and MUST independently decode the optional `appendText` (a string) and `removeText` (an integer) fields only when `indentAction` decodes successfully.
- **integer-fields-read-via-exact-conversion**: decoding `indentAction` and `removeText`, and the word-pattern refusal check's downstream numeric comparisons, MUST convert a JS number to an integer using an exact-value conversion that refuses any value not exactly representable as that integer, never using JavaScript's truncating/wrapping `ToInt32` conversion; a value whose `ToInt32` wraparound happens to land on a valid range (for example `4294967297` wrapping to `1`) MUST be refused rather than silently accepted as that in-range value.
- **on-enter-rule-requires-before-text-and-action**: decoding an on-enter rule value MUST decode to nothing for the entire rule when `beforeText` fails to decode as a regex value or `action` fails to decode as an enter action value, and MUST independently decode the optional `afterText` and `previousLineText` fields only when both required fields are present.
- **on-enter-rule-array-drops-invalid-entries**: decoding an array of on-enter rule values MUST drop any array element that fails an on-enter rule value's own decode while keeping every valid sibling element, rather than failing the whole array when one entry is malformed.
- **syntax-token-type-raw-values**: `SyntaxTokenType` MUST expose `other == 0`, `comment == 1`, `string == 2`, and `regEx == 3`, matching `vscode.d.ts`'s declared numeric values exactly.
- **syntax-token-type-array-drops-invalid-elements**: decoding an array of syntax token type values MUST read each element through an exact-value integer conversion and drop any element that is not a JS number mapping to a defined `SyntaxTokenType` case, rather than failing the whole array.
- **auto-closing-pair-shape**: decoding an auto-closing pair value MUST decode to nothing unless the source value is an object with string-valued `open` and `close` properties, and MUST decode an optional `notIn` array of syntax token type values, leaving `notIn` absent when that array is absent or entirely invalid.
- **auto-closing-pair-array-drops-invalid-elements**: decoding an array of auto-closing pair values MUST drop any array element that fails an auto-closing pair value's own decode while keeping every valid sibling element.
- **language-configuration-never-fails**: decoding a language configuration value MUST return a value with every member absent — never raise, never fail the decode outright — when the source value is `undefined`, `null`, or not an object, so that an unusable second argument to `setLanguageConfiguration` reads as "nothing configured" rather than raising a script-engine exception.
- **language-configuration-members-decode-independently**: decoding a language configuration value MUST decode each of `comments`, `brackets`, `wordPattern`, `indentationRules`, `onEnterRules`, and `autoClosingPairs` independently from the source object's own like-named property, so a failure decoding one member MUST NOT prevent any other member from decoding successfully.
- **deprecated-members-accepted-and-dropped**: decoding a language configuration value MUST accept a configuration object carrying `__electricCharacterSupport` or `__characterPairSupport` without raising, and MUST NOT store either member's value anywhere or report it through any deprecation channel.
- **language-configuration-store-keyed-by-handle**: the language configuration store MUST key its registrations by an opaque, monotonically increasing integer handle assigned when a configuration is registered, never by `languageId`, so two registrations for the same `languageId` MUST both persist as independent entries.
- **handle-assignment-is-monotonic**: the language configuration store's internal handle counter MUST start at `0` and increment by exactly `1` on every registration, and a handle removed by a removal operation MUST NOT be reassigned to a later registration.
- **remove-handle-is-idempotent**: removing a registration by handle MUST be a no-op — MUST NOT raise or otherwise fail — when the handle does not currently name a live registration, including when it names one already removed.
- **configurations-for-language-ordering**: looking up the registrations stored for a given language MUST return every registration currently stored for that language, ordered by ascending handle (oldest registration first), and MUST return an empty array when none are registered.
- **main-thread-languages-requires-injected-collaborators**: this component's construction MUST take both the language configuration store and the language vocabulary as required collaborators with no default value, so a caller cannot silently receive a private store or an empty vocabulary in place of the host's real ones.
- **get-languages-rejects-when-torn-down**: `getLanguages` MUST be published with a torn-down response of a rejected promise, so a call reaching an instance of this component that has already been deallocated MUST resolve to a rejected `Thenable` rather than raising an exception, matching the external API's declared `Thenable<string[]>` return type.
- **get-languages-answers-fresh-from-vocabulary**: answering a `getLanguages` call MUST read the language vocabulary's identifiers anew on every call and MUST wrap the result in an already-resolved promise via the shared already-resolved-promise helper; it MUST NOT cache the vocabulary's answer across calls.
- **get-languages-ignores-extra-arguments**: answering a `getLanguages` call MUST NOT read or validate any call arguments, matching `vscode.d.ts`'s declaration of `getLanguages()` with no parameters.
- **get-languages-answer-is-independent-per-call**: each call to `getLanguages` MUST produce a JS array distinct from any array returned by a prior call, so that an extension mutating one call's resolved array (push, sort, or otherwise) MUST NOT change what a subsequent call resolves with.
- **set-language-configuration-requires-string-id**: answering a `setLanguageConfiguration` call MUST raise a JavaScript error with the exact message `setLanguageConfiguration requires a string language id.` and MUST NOT add a registration to the store when the first argument is absent or is not a JS string.
- **set-language-configuration-accepts-empty-or-missing-second-argument**: answering a `setLanguageConfiguration` call MUST treat a call with no second argument identically to one whose second argument is `undefined`, `null`, or a non-object primitive — all decoded as a language configuration value with every member absent, with the call MUST NOT raising for that reason alone.
- **set-language-configuration-raises-when-torn-down**: `setLanguageConfiguration` MUST be published with a torn-down response of a raised exception, so a call reaching an already-deallocated instance of this component MUST raise a synchronous exception rather than answering a rejected promise, matching `vscode.d.ts`'s synchronous `Disposable` return type.
- **word-pattern-refusal-order**: answering a `setLanguageConfiguration` call MUST evaluate the word-pattern refusal check against the translated `wordPattern` before adding the registration to the store, so a refused `wordPattern` MUST result in no registration being added to the store.
- **word-pattern-empty-match-refusal**: the word-pattern refusal check MUST return the message `Invalid language configuration: wordPattern '<pattern>/<flags>' is not allowed to match the empty string.` (with `<pattern>/<flags>` rendered as `/pattern/flags`) when the `wordPattern` compiles successfully under the platform's regex engine and matches the empty string at a zero-length range, unless its `pattern` source is exactly one of `^`, `^$`, `$`, or `^\s*$`.
- **word-pattern-exempt-patterns-are-source-exact**: the word-pattern refusal check MUST compare a `wordPattern`'s exempt status against its `pattern` source text verbatim, independent of its `flags`, so a pattern spelled differently but functionally equivalent to one of the four exempt sources MUST NOT be treated as exempt.
- **word-pattern-compile-failure-is-not-a-refusal**: the word-pattern refusal check MUST answer with no refusal when `wordPattern`'s `pattern` fails to compile under the platform's regex engine, and the configuration's `wordPattern` MUST still be stored unvalidated in that case rather than the whole `setLanguageConfiguration` call being refused.
- **word-pattern-compile-failure-is-logged**: when a `wordPattern` fails to compile under the platform's regex engine, this component's logger MUST log an error including the pattern's `/pattern/flags` rendering and the caught error's localized description.
- **word-pattern-absent-is-not-refused**: the word-pattern refusal check MUST answer with no refusal when the translated configuration's `wordPattern` is absent, whether because no `wordPattern` property was supplied or because the supplied value failed to decode as a regex value.
- **set-language-configuration-returns-scoped-disposable**: on success, answering a `setLanguageConfiguration` call MUST return a `Disposable` whose disposal removes exactly the one handle just added from the store and from this adaptor's own set of owned handles, and MUST insert that handle into its owned handles before returning.
- **dispose-removes-only-owned-handles**: disposing this component MUST remove from the store every handle in this instance's own owned handles and MUST clear that set, and MUST NOT remove any registration added by a different instance of this component sharing the same store.
- **extension-language-vocabulary-contract**: the language vocabulary MUST expose a `languageIdentifiers` list of strings, deduplicated and in a deterministic order, per the vocabulary's own documented contract.
- **languages-member-not-tracked-as-unimplemented**: `setLanguageConfiguration` and `getLanguages` MUST NOT be routed through the shared ledger that records unimplemented API members, because both members answer every call rather than being absent.
- **confines-to-ui-thread**: The component MUST be usable only on the UI thread.
