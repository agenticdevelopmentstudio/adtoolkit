
- **activation-state-precedence**: The host's activation state MUST evaluate in the fixed order disposed, activated, terminal, activating, not-yet-activated — never in field-declaration order — so that a cancellation landing after a successful activation is still reported as activated, and a failure recorded while activation is being performed outranks the activating state a racing caller might still observe.
- **activate-idempotent-shared-outcome**: Activating the host MUST be a no-op that returns immediately when the activation state is already activated, and two concurrent callers MUST share the single in-flight activation task rather than each evaluating the module.
- **activate-refuses-when-disposed-or-terminal**: Activating MUST throw a host-disposed error on a disposed host, and MUST throw the mapped cancelled/already-failed error on a terminal host, without re-evaluating the module.
- **activate-no-timeout**: Activating MUST NOT impose an internal timeout on an extension's own `activate()` promise; the only two ways to end a suspended activation are cancelling the calling task (which reports as cancelled) and disposing the host.
- **activate-cancellation-shared**: A cancellation from any one caller of activate MUST end the shared activation for every other awaiting caller.
- **module-evaluated-terminal-boundary**: The module-evaluated flag MUST be set exactly once, immediately before the module's run call, and every route into the terminal state MUST test this flag rather than infer it from which step of evaluation it is inside.
- **failure-before-boundary-is-retryable**: A failure that occurs before the module-evaluated flag is set (entry-point resolution, disk read, compile) MUST leave the host not-yet-activated and eligible for a later activate call.
- **failure-after-boundary-is-terminal**: Any failure at or after the module's run call (a synchronous throw, a rejected `activate()` promise, a throwing `.then` getter, a top-level throw, or a cancellation landing once the module is running) MUST record a termination reason and MUST refuse every later activate or define-vscode-member call on that host.
- **terminal-reason-keeps-first**: Recording a termination reason MUST keep the first reason recorded and MUST be a no-op on every subsequent call, so a cancellation and a failure racing to the same boundary cannot overwrite each other's diagnostic.
- **dispose-idempotent**: Disposing the host MUST be safe to call more than once and safe to call on a host that never activated.
- **dispose-releases-suspended-activation**: Disposing MUST resume any suspended activation with a host-disposed error, since an extension's own `activate()` promise may never settle and there is no timeout to fall back on.
- **dispose-cancels-every-timer**: Disposing MUST cancel every outstanding timer task and clear the tracking table, so no `setTimeout`/`setInterval` task can reach JavaScript again after teardown.
- **dispose-releases-context**: Disposing MUST replace the execution context's exception handler with one that safely records the exception, rather than clearing it, since the underlying engine calls whatever handler is set unconditionally, and MUST release the activation context, the runtime, and the execution context itself.
- **dispose-subscriptions-before-context**: Disposing MUST dispose the activation context's subscriptions before releasing the execution context, so the extension's own disposables are still callable at the moment they run.
- **dispose-subscriptions-idempotent**: Disposing the activation context's subscriptions MUST run at most once per host, so a caller (such as an installation's own dispose operation) that calls it ahead of the host's own dispose produces exactly one pass over `context.subscriptions`.
- **dispose-subscriptions-releases-values-promptly**: Disposing the activation context's subscriptions MUST release each JavaScript value it produces promptly rather than deferring their release to the end of the whole pass, because every JavaScript value produced along the way holds its own execution context strongly and would otherwise keep the context alive past the promise disposing makes to release it.
- **finalization-safety-net-cancels-timers**: The host's own finalization MUST cancel every timer task as a safety net for a host dropped without an explicit dispose call, but MUST NOT be relied upon as the primary teardown path, since a host with an in-flight activation task (which strongly captures the host) never reaches finalization at all.
- **define-vscode-member-refuses-terminal-or-disposed**: Defining a vscode member MUST throw a host-disposed error on a disposed host and the mapped terminal error on a terminal host, never silently queuing a definition nothing will replay and never installing a live implementation into an abandoned runtime.
- **define-vscode-member-replays-on-runtime**: A definition made before a runtime exists MUST be queued and applied immediately once the runtime is installed; a definition made after activation MUST be applied immediately.
- **define-vscode-member-withdraws-on-refusal**: A definition the shim refuses (an unknown namespace) MUST be removed from the queue rather than left there, so the host remains activatable and the same bad definition does not fail every future activate call.
- **deferred-value-resolved-at-apply-time**: A deferred value's implementation MUST be resolved against a live JavaScript execution context only at the moment it is applied, never at the moment the member is defined, since every caller defining a member runs before any context exists.
- **live-value-re-read-per-access**: A live value's implementation MUST be re-read on every JavaScript access rather than resolved once and cached, so members reporting app state (`vscode.workspace.workspaceFolders`, `vscode.workspace.name`) never freeze to whatever was true at install time.
- **timer-delay-clamped-nan-safe**: Computing a timer's clamped delay MUST compute the equivalent of `min(max(0, milliseconds), maximum delay) / 1000`, with `0` as the first argument to the max comparison (not the second), so that a `NaN` delay collapses to `0` rather than propagating into a duration value that traps on an unrepresentable input.
- **timer-cancel-validates-before-truncating**: Cancelling a timer MUST validate that the raw numeric id is finite, integral, and within the 32-bit signed integer range before truncating it, and MUST do nothing (never round onto an unrelated timer) when validation fails.
- **timer-task-count-asserts-not-clamps**: Recording that a timer task finished MUST assert and log a fault rather than clamp to zero when the running-timer count is not already positive, since a double-decrement indicates a timer task finished twice, a bug this counter exists to surface rather than hide.
- **console-message-always-logged**: Every `console.*` call MUST produce a log line at the mapped level, and MUST additionally invoke the console-message observer when one is set, even when no observer is attached.
- **not-implemented-recorded-once-per-member**: A member reached for that this host does not implement MUST be recorded in the ledger, with only the first access producing a log line, so a member reached for in a loop does not flood the log.
- **negative-probe-recorded-separately**: A feature-detection probe (`'x' in vscode.commands`, `Object.keys(...)`) that finds nothing MUST be recorded, sharing the same ledger row as a hard use of the same member but incrementing its probe count rather than its use count.
- **entry-point-requires-browser-not-main**: Resolving the entry point MUST throw a requires-Node-runtime error when the manifest declares `main` but not `browser`, and MUST throw a no-entry-point error when it declares neither, never treating a Node-only extension as a generic load failure.
- **entry-point-must-not-escape-directory**: Resolving the entry point MUST resolve the declared `browser` path through the shared resource-path resolver and MUST throw an entry-point-escapes-directory error when the resolved path falls outside the extension's own directory, including a sibling directory sharing a name prefix.
- **compile-runs-nothing**: Compiling the module MUST produce a callable closure without executing any of the extension's top-level statements, which is the property that allows the compile step alone to run off the host's own execution context.
- **entry-point-attributed-in-stack-traces**: Compiling the module MUST attribute the wrapped source to the entry point's own location, so a syntax error or a thrown exception names the extension author's own file and line.
- **exports-required-non-empty**: Evaluating the module MUST throw an entry-point-threw error when the module's run call yields `undefined`/`null` exports, distinct from a thrown exception.
- **activate-absence-is-not-an-error**: Calling activate MUST log (not throw) when the module's exports have no `activate` function, since a manifest-only extension that contributes solely through side effects is legal.
- **activate-rejection-getter-throw-reported**: Calling activate MUST report a thenable whose `.then` property getter throws as an activation failure, rather than hanging indefinitely because the shim's completion callback is never invoked in that case.
- **finish-activation-resumes-exactly-once**: Finishing activation MUST resume the stored, suspended activation at most once and MUST be a safe no-op when nothing is pending, since up to four routes (the shim's completion block, the thenable-getter-throw path, disposing the host, and a cancelling caller) can race to end the same activation.
- **describe-reentrancy-bounded**: Describing an exception MUST return a fixed literal string rather than recursing when called while already describing another exception, so a hostile self-referential `Proxy` that throws while being described cannot overflow the native stack.
- **vscode-uri-and-vocabulary-installed-eagerly**: Installing the runtime MUST install the command-dispatch trampoline, `vscode.Uri`, the language-model message vocabulary, the text-geometry classes, and the diagnostic value types on every activation, before any adaptor-registered member and before the extension's own module code runs, and MUST NOT route any of these five through the define-vscode-member queuing path, since they are host ceremony reinstalled identically every time rather than adaptor state to be replayed.
- **install-vscode-members-sorted**: Installing vscode members MUST iterate the member table's keys in sorted order, never in raw, unordered iteration order, so the install order (and therefore any log line describing a failed install) is stable across runs.
- **host-globals-removed-after-shim-setup**: Installing the runtime MUST remove the runtime-setup globals (`globalThis.__extensionRuntime`, `globalThis.__host`) after wiring the runtime, so extension code has no direct line to the host's timer/console/ledger bridge once setup is complete.
- **installation-adaptor-teardown-order**: Disposing an installation MUST run, in this exact order: dispose the host's activation-context subscriptions; unregister every remaining entry in the activation-stub command table; dispose all eight adaptors (commands, languages, workspace, language models, window, webviews, tree views, diagnostics); then dispose the host itself last — because the adaptor withdrawals call back into JavaScript (a panel's `onDidDispose`, a tree view's teardown) and require a live runtime.
- **installation-dispose-idempotent**: Disposing an installation MUST be a no-op on a second call.
- **activation-command-double-press-forwards-both**: Dispatching a command after activation MUST retire its stub token only if present, without requiring it, before forwarding, so that a second command press queued while activation is still in flight is forwarded on its own merits rather than dropped because the token was already taken by the first press.
- **activation-stub-leaves-owned-commands-alone**: Registering activation-stub commands MUST NOT register a stub over a command id already present in the command registry, and MUST log that the extension's `onCommand:` trigger for that id will never fire.
- **installer-reconcile-identity-not-identifier**: Reconciling the running set MUST key "already installed" on the manifest plus directory plus the entry point's own file signature (size and modification date), never on the bare extension identifier, so an author's on-disk code edit is detected and the host is rebuilt even when the manifest is unchanged.
- **installer-reconcile-dispose-before-rebuild**: Reconciling MUST dispose an outgoing installation before constructing its replacement for the same identifier, never leaving both live at once, since both would otherwise record against the same extension identifier in five adaptors simultaneously.
- **installer-reconcile-disables-removed-extensions**: Reconciling MUST dispose and remove every installation whose identifier is no longer in the enabled set.
- **installer-bring-up-replays-completed-scan-only-if-current**: Bringing up a newly installed extension MUST replay the workspace-scanned activation trigger against it only when the completed scan's roots still equal the live workspace roots, never a stale scan from a since-closed project.
- **installer-bring-up-replays-open-documents-live**: Bringing up a newly installed extension MUST replay document-opened triggers by reading the open-document languages live at call time, never from a remembered set, so a document since closed cannot activate an extension.
- **workspace-scan-reused-per-workspace**: Starting a workspace scan if needed MUST reuse the completed scan when its roots already equal the live workspace roots, and MUST NOT start a second scan while one with the same roots is already in progress.
- **workspace-scan-race-safe-on-root-return**: The workspace scan's completion handler MUST re-read the live workspace roots and discard a scan's result (retrying rather than recording it) when the live roots no longer match the roots the scan was started against — covering an A-to-B-and-back-to-A root change during an in-flight scan of B.
- **workspace-scan-depth-and-entry-capped**: Scanning the workspace roots MUST stop descending into a directory once the walk's depth reaches the depth limit (6) and MUST stop collecting once the number of found entries reaches the entry limit (20,000).
- **workspace-scan-skips-generated-directories**: Scanning the workspace roots MUST skip descending into any directory named in the skipped-directory-names set (`.build`, `.git`, `.svn`, `.venv`, `DerivedData`, `Pods`, `__pycache__`, `build`, `dist`, `node_modules`, `target`, `vendor`).
- **workspace-scan-includes-dotfiles**: Scanning the workspace roots MUST NOT skip hidden files while walking, so dotfile-based `workspaceContains:` patterns (`.vscode/launch.json`, `.eslintrc*`) remain matchable.
- **workspace-scan-failure-is-silent**: Scanning the workspace roots MUST resolve each directory entry's directory-or-file status, defaulting to "not a directory" on any failure and continuing the walk; the completed-scan result carries no incompleteness flag, so the answer to a `workspaceContains:` pattern is always presented as complete even when the walk could not read every entry.
- **webview-panel-claim-order-deterministic**: Restoring a webview panel MUST resolve a webview view-type contested by more than one installed extension by sorting claimants by identifier and choosing the first, and MUST log when more than one claimant exists.
- **contributed-view-resolved-by-manifest-ownership**: Resolving a contributed webview view or tree view MUST resolve strictly to the single extension named as its owner in the manifest, never by a claims-based contest, since a contributed view's ownership was already declared in the manifest.
- **contributed-view-will-appear-is-a-broadcast**: A contributed view about to appear MUST notify every installed extension's activation-trigger check for that view being shown, unlike the owner-only resolution operations, because `onView:` may be declared by any extension against any view id, including one it does not own.
- **not-implemented-ledger-dedup-by-key**: The ledger MUST deduplicate by extension identifier and member path together, keeping the first access timestamp and incrementing its use count (for a hard use) or its probe count (for a feature-detection probe) on every subsequent call for the same key.
- **not-implemented-ledger-accessors-sorted**: The ledger's two read operations (all accesses, and accesses for one extension) MUST both return rows ordered by extension identifier then member path, never in insertion order.
